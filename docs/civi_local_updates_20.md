## 结论与唯一建议

最支持 **③：当前初始化存在可由同一个 Renderer 利用的 Contact 共同下降方向**。20 步共享更新将预测响应实现 MSE 降低 **9.74%**，真实 Teacher 响应 MSE 降低 **5.52%**，而且 4 个 Contact 各自均改善。单样本网络更新也有效，其自身样本平均 MSE 降低 12.29%，不支持“单样本网络也很难动”的强判断。

确有样本间有限步干扰：B 的 12 个非自身 Contact 评估全部恶化。但 C 的共同改善表明，不能据此认定共享参数更新明显受阻。三组幅度匹配未成功，且 C 增加了两个 Free 的微小非零响应；因此不能把 A/B/C 的改善差距解释成网络容量差距，也不能声称这些 Contact 方向一定改善原来的总训练目标。

**唯一建议的下一步（本次未执行）：** 固定同一初始化、同一训练小批次及 FP32 评估，只核对“原训练实际一步更新”与本轮纯 Contact 平均 MSE 更新的方向对齐、实际 RGB 位移及 Free 代价，以判断原目标/更新过程是否压低了这些已有方向。先做这一项核对，再决定是否训练；本次不继续优化或开启结构搜索。

## 响应与公平性口径

所有优化、起点和终点评估均重新使用 **FP32**：Renderer、固定 gates/alpha、DINO、投影/位置与相机嵌入、已校准 Adapter、context_norm、Predictor、Teacher 和损失；禁用 autocast、TF32、Dropout、MHA fastpath 及 Flash/Memory-efficient SDP，启用确定性算法。逐样本（batch=1）使用同一路径；同一初始渲染以及 grad/no-grad 读出被检查为逐元素相同。未引用或混合历史 BF16 指标。

`E = 冻结 DINO + 投影/嵌入 + 已校准 Adapter + context_norm`；`dS = E(rendered_RGB)-E(original_RGB)`；唯一显式损失 `L = mean((dS-dP)^2)`，覆盖全部 784×256 个响应元素，不按 active patch 筛选。`dP` 由匹配 Predictor 对原图 FP32 视觉 token 重新计算一次，随后冻结；三组使用完全相同的 dP。它不是把旧 FP16/BF16 读出指标当作当前起点。

真实教师响应 `dT = Teacher(obs)-Teacher(physical_zero_wrench_obs)` 也重新 FP32 计算，物理零在归一化之前构造。表中真实教师响应 MSE 为 `MSE(dS,dT)`，不是绝对 token MSE。响应余弦分别对整条 dS/dP、dS/dT 向量计算，再取窗口均值。两个 Free 的 dT 为零，其对零向量的余弦约定为 0，不作方向解释。Free 梯度只为一阶检查使用同一 dP 损失，绝不加入 optimizer 更新。

每个窗口的原始 spatial gate 和 alpha 只计算一次，三组共用。每个通道均满足 `[max(0,original-0.1*support), min(1,original+0.1*support)]`，其中 `support=spatial_gate*alpha`；不支持的像素严格等于原图。每次报告均断言这些约束。RGB 更新 RMS 为 `RMS(output-initial_render)`；总 RMS 为 `RMS(output-original)`，跨时间、相机、像素和 RGB 通道；汇总 RMS 是先汇总平方再开根号。二者不可混用。

## 对三种解释的区分与边界

1. **① 像素能改善，但单样本网络也难改善：不作为主要结论。** A 有改善，B 四个自身样本也分别改善 8.10%–21.20%。A 更强不足以证明 B 无法表达，尤其未做到三组等 RMS。
2. **② 单样本有效而共享明显受阻：仅有“存在干扰”的部分证据。** B 会损害其他 Contact；但 C 平均改善 9.74%、每个 Contact 都改善，且 B/C RGB 修改量有差别，不足以判定共享明显卡住。
3. **③ 共享更新也有效：本次最支持。** 当前初始化下仍存在 Contact 的共享可用方向；原训练可能未充分利用，也可能因为 Free 或其他原目标的代价而没有继续沿此方向，须保留这一区别。

这些都只是当前初始化、固定 6 个训练窗口和短 20 步的局部诊断，不证明全局不可表达，也不证明泛化或最终策略收益。没有验证集调参、后续结构搜索或新的训练。
